# ch08-update-2026-10-19

**Objective.** After chapter 8 the reader can update focus-kit knowing how the update tells an edit of theirs from the kit's own change, reads its report as a list by document and section, where an item is a migration, a match or a choice the team recorded, knows which command comes next on a documented project, and knows which copy of a command Copilot runs when the skill is in both skills folders.

**Behaviour.**

* The reader explains when an update may replace a kit file: when it matches a file the kit shipped, in this version or a prior one verified from the kit's history (`git show <commit>:SETUP.md` in the kit's repository) or, without that history at hand, by the person's word that the file was never edited; a familiar name or a `metadata.version` alone does not prove it.
* Given a line they added by hand to `.claude/skills/propose/SKILL.md`, the reader expects the update to show that edit as a diff against the kit file it was made on, the kit's own change to that file since apart and in short, to stop before writing or removing any file, and still to report the migrations and the next command; they decide whether to keep or replace their edit, and know that a rule their edit added to a command can become a slot of docs/05 §5, which the commands follow (chapter 7).
* The reader knows this check holds on a real run: on a copy of the book's kit files, outside the repository, an appended line in `propose/SKILL.md` stopped the update to 2026.10.19 this way and left every file of the copy unchanged. The chapter never says the update stopped on the book's repository: it did not.
* Given the excerpt of the report the update to 2026.10.19 gave on the book's repository, the reader reads each item as a document and a section with one of three outcomes: it matches and needs nothing (`none`); it lacks something, with the wording proposed (docs/05 §4, where a board sees a mark, or §6, the one index); or it differs by a choice the project recorded with a date, reported as that choice with what the kit says, not as a migration (docs/05 §5 Milestone review, the kit's readers, recorded on 2026-10-17). Every item is reported, never done.
* The reader knows the report checks docs/05's section numbers first, because the commands cite the template's numbers and read by number.
* On a documented project, the reader expects the update to report the migrations first, or say there are none, not to ask for `/brainstorm` or `/analyze` again, and to name the command docs/06's first free line wants: `/propose` for a `[ ]` line, `/apply` for a `[>]` one, in their host's form.
* The reader knows that Copilot finds a skill of the same name in `.agents/skills/` before `.claude/skills/`, the first found wins, and the kit writes the same file in both, so either copy is the same command.
* Edge: the reader who already runs the current version expects a rerun to write nothing; the chapter states no count of files, lines or items for any kit change.
* Fails: an excerpt item that the record does not support, a sentence implying the refusal touched a real file, or a before/after of the kit's versions in the text; /apply removes it before verify.
