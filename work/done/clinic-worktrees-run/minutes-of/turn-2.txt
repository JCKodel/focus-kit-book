**What I chose and why:**
- **The shared copy goes in `src/lib/time.ts`.** docs/01 says code moves to `lib/` on its second concrete use, and this is the second. `appointments/rules.ts` already imports a type from `weeklyHours/rules.ts`, but a shared function shouldn't live inside one feature for another feature to reach into. The file is named after what it reads, as `name.ts` and `email.ts` are.
- **`minutesOf` keeps returning a plain number, not a `Result`.** Neither caller can pass a bad time: `setWeeklyHours` checks it first, and `freeSlots` reads periods that were checked before they were stored. A comment says it trusts its input.
- **The time-format check (`validTime`) stays where it is.** Only one feature uses it, so it moves when a second one needs it.
- **Three small tests in `src/lib/time.test.ts`** (00:00, 09:30, 23:55), because every `lib/` file has its own test.
- **Nothing is added to docs/03.** This is a code helper, not clinic vocabulary. The page tells `/apply` to add `time.ts` to docs/01's `lib/` listing.
