**Behaviour.**

* With every line in this review's `after` `[x]`, /apply builds both PDFs at the end commit, reads in both the passages the clause table below names, at their start pages, and answers each clause's question itself: holds, or fails with what the passage says. The page records these answers as the review's, never the author's: the author reads no PDF in this run and tests no clause (docs/05 §8, the paragraph on the person's word).
* The review compares the installed commands and scripts with focus-kit 2026.10.20.5 as `work/done/kit-2026-10-20-5.md` records it (SETUP.md at the kit's `cc16f4e`, the changelogs at `870bb13`), checks that docs/05's range diff is exactly the three edits that record's Contract names, the four waiting cases (docs/05 :137 to :141) untouched, then checks the book's explanations against those files.
* The author's word that starts the readers and hands the review its tests is already given, relayed by the batch's driver and quoted under Decisions taken alone. /apply records the end commit, then launches read-only area readers over one fixed range, `git diff <base>..<end>`; one checker tests each candidate against that same snapshot and labels it seen, latent or weak.
* The readers and the checker report back to the review's own session, the one running /apply, never to the driver: the session launches each as a foreground Agent call and receives its final report itself, as the call's result. A checker's marks that reach the session only through a working file or another session's summary are not its report; the session then asks the checker again, or the line waits as below. Working files go under the session's scratchpad directory, in its `m29/` folder; the review writes its candidate table to `m29-candidates.md` at the top of that scratchpad directory, beside the folder, then copies it onto this page.
* Each candidate the checker marks seen, low ones included, becomes a `[ ]` line under this review in docs/06, candidates sharing a file or a cause sharing a line; every latent and weak candidate is dropped and listed on this page with its mark. No fix is made here.
* A clause with no answer, a required reader that cannot run, a checker whose report does not reach the session, or paths of the range no reader read leave this review waiting as `[?]` with `· resume: apply` and the reason (docs/05 §§4, 8); a partial reading that found nothing never closes it.
* A commit made during the reading does not move the end commit; what it changed is named as outside this reading.
