## 1. Where the model is

Short version: the lending rules are in code, tested, and Odile has read the test list end to end and signed it off (1 Sep).

| area | state |
|---|---|
| books | Book vs Copy, statuses available / on-loan / withdrawn, withdraw with who+when |
| members | register (email validated), suspend with reason/date/librarian, reinstate |
| librarians | staff record, separate from members |
| loans | checkout, return, renew; 21-day period, max 5 active, max 2 renewals, no renewing overdue loans, overdue members can't borrow |
| suspension | more than 14 days overdue → suspended via `applySuspensions`; any librarian lifts it once nothing's overdue |
| shared | `Result` + kebab-case error codes; calendar-date strings |
| tests | `node --test`, no dependencies, all green, runs in about a second |

Things deliberately **not** in the model: fines (none), email reminders (parked), CardBox import (decided against in Aug), opening hours/closures (handled by staff).

Not done: **reservations / holds.** There's a draft by Juno and Marek (`holds-and-reservations-DRAFT-v2.md`) — still a draft, not implemented, no code. Same for Rafe's `Loan Service Design (draft).md`: open, being discussed, nothing built from it yet.

## 2. Candidates for next quarter

Each person pitched 2 min. Rough sizes from TO/RL.

**a) Desk UI (minimal)** — RL
Something a librarian can actually use: look up member, scan copy id, check out / return / renew, see refusals as readable messages. Needed anyway for re-entering active loans from the cards. *Size: L.* Depends on (b).

**b) Persistence** — TO
The model is pure functions over arrays. Need somewhere to keep members, copies, loans between runs. Options: single file, embedded DB. Leaning simplest thing that survives a power cut. Rafe's service draft is the natural starting point for the layer between storage and model. *Size: M.*

**c) Reports** — BA, MS
Printable lists for the desk: overdue loans, members due for suspension, loans due in the next 3 days (the cheap version of the reminders idea), copies withdrawn this month. Mostly queries on what exists. *Size: S–M.* Can be done before (b) against test data.

**d) Reservations / holds** — JA, MS
Continue from the v2 draft. Odile's interest is moderate: "people ask at the desk, it works". *Size: M,* plus open questions in the draft.

**e) Second branch** — nobody pitched it; Odile confirmed nothing's planned.

Discussion: Marek pointed out (c) is the only one that delivers something to Wren within weeks. Rafe worried that UI without storage is a demo, not a tool. Bex wants a test fixture "library" (a few dozen members, copies, loans) before any of it — useful for all three.
