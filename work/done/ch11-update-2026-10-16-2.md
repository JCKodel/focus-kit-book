# ch11-update-2026-10-16-2

**Objective.** After chapter 11 a reader installs the kit with the sentence its README gives, reads an update report at the current version and knows what each migration it names asks of the project's documents, and knows what a rerun writes into a worktree Git slot that names no folder.

**Behaviour.**

* A reader who copies the install sentence from the chapter gets the kit's README's own sentence, which fetches the raw file: an agent that follows it reads the whole setup file and not a rendered page.
* A reader who runs the update on a project at the previous version reads, in the chapter, a report whose items are the ones the kit's setup file checks today: the flow's line and draft, the Contract's reasons, the Milestone review slot, the Publish policy's last sentence, the gate's wording, the review that reads the code, and `AGENTS.md`'s line; they recognise each in their own report.
* Failure: a reader whose report names an item the chapter does not explain (a migration the chapter's example lacks) cannot tell a rule from a wording change. The chapter says which items change a rule and which change only words, as it does today for its items.
* A reader whose docs/05 chose a worktree per delivery and whose container's hidden folder already holds `repo.git/` reads that the rerun writes that folder's name and the prefix its branches use into the Git slot, so nothing moves; one with no container reads that a slot naming neither means the kit's default (chapter 21 names it).
* Edge: the report's versions are the command's output and stay; no other sentence of the chapter names a version as a date (docs/04, the kit as it is).
* Edge: a reader on OpenCode or Zed finds their host in the table, invoking a command by asking for the skill, as the kit's table has it.
