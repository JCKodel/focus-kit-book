# kit-2026-10-13

**Objective.** After this delivery the repository runs focus-kit 2026.10.13: every host's command files are the kit's, docs/05, docs/04, docs/03, AGENTS.md and the queue carry the migrations the kit's setup reports, and a person who wants to publish the site, release the book or set up the disclosure list finds a manual for it in `docs/manuals/`.

**Behaviour.**

* Opening `.claude/skills/propose/SKILL.md` (or any of the four skills under `.claude/skills/`, `.agents/skills/`, `.windsurf/skills/`) shows `version: "2026.10.13"` and reads byte for byte as `SETUP.md` §3 at kit `96c0930` writes it; the same holds for `.agents/skills/*/agents/openai.yaml`, `.github/prompts/`, `.cursor/commands/`, `.gemini/commands/`, `.agents/rules/focus-kit.md`. `GEMINI.md` is unchanged (its pointer line is already the template's).
* If a planted file differs from every shipped kit version (today's install is 2026.10.05, kit `0878434`), /apply stops before writing any file, shows the diff and marks the line `[?]`; nothing is half-installed.
* `git diff --stat` after the reinstall lists no kit file outside the paths of SETUP.md §3, and `docs/`, `work/`, `AGENTS.md`, `CLAUDE.md` change only by the edits below.
* Reading docs/05 §2, a person finds that a code change asked outside /apply becomes a `[ ]` line and the answer stops there, and the paragraph on what /propose does before changing the queue.
* Reading docs/05 §3, a person finds Behaviour asked as an action with concrete input and the result seen, with failure cases and edges; that the done page ends in one `commit` block; and that a page with an open scope question is not `[>]`.
* Reading docs/05 §4 and the header of docs/06, a person finds that the order is the priority, that `· after <slug>` is an order and not a block, the `· resume: propose|apply` suffix, and that two sessions in one tree on free lines touching different files are normal.
* Reading docs/05 §6, a person finds the commit format the book uses (`<type>(<slug>): <subject>`, types `feat`, `fix`, `docs`, `chore`) and the staging rules; docs/04 §Commit messages says only that docs/05 §6 owns the format.
* A person who opens `docs/manuals/release-the-book.md` with nothing else read can release the book: what it does and when, what must be in place (main clean, not behind, verify green, the list), `make release` and `BUMP`, how to tell it worked (the Release with four files), how to undo it (delete the Release and the tag), what breaks if a step is skipped. The same six parts in `publish-the-site.md` and `set-up-the-disclosure-list.md`.
* A manual that contains a term of the disclosure list fails `make scan`; a manual with an em dash fails `make verify`.
* docs/05 §5's Environments (Pages, Release) and Disclosure slots keep their commands and point to their manuals instead of holding the steps; the Manuals slot lists the three.
* AGENTS.md has the line on `docs/manuals/`, the code-only clause, the stage-only line and the "where things stand" line, and stays at sixty lines or fewer.
* The seven M12 lines ending `· after kit-2026-10-13` keep the suffix when this line becomes `[x]`; the line `ch13-16-queue-order` no longer says "docs/03 gains the term".
